# 测试与质量门禁

## 原则

项目默认测试必须：

- 离线运行。
- 不访问付费 API。
- 不依赖开发者本机真实密钥。
- 对并发、恢复、预算、引用追溯和安全边界给出可重复断言。

`tests/conftest.py` 负责隔离真实凭证和清理配置缓存。新增测试不得绕过该隔离。

## 后端检查

从项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\ruff.exe check src tests evals
.\.venv\Scripts\ruff.exe format --check src tests evals
.\.venv\Scripts\mypy.exe
```

不要在文档中长期写死“有 N 个测试”；以当前命令输出为准。

## 前端检查

```powershell
cd web
npm test
npm run typecheck
npm run build
```

浏览器 E2E：

```powershell
cd web
npx playwright install chromium
npm run test:e2e
```

Playwright 配置会启动后端和 Vite。若浏览器二进制尚未安装，单纯存在 E2E 脚本不等于浏览器测试通过。

## 重点测试区域

| 主题 | 代表测试范围 |
|---|---|
| 配置与密钥 | `test_config.py`、`test_secrets.py` |
| Provider | `test_health_and_provider.py`、`test_qwen_provider_contract.py` |
| 状态与调度 | `test_state_reducers.py`、`test_supervisor_routing.py`、`test_graph_e2e.py` |
| 预算与恢复 | `test_reflection_budget_errors.py`、`test_replan_and_checkpoint.py`、`test_sqlite_recovery.py` |
| 抓取与提取 | `test_fetchers.py`、`test_extractor_and_writer.py` |
| 可信报告 | `test_verified_report.py`、`test_verified_e2e.py` |
| API | `test_api_routes.py`、阶段接受测试 |

| 前端安全 | `App.test.tsx`、`SafeMarkdown.test.tsx` |
| 浏览器链路 | `web/e2e/app.spec.ts` |

## 修改后最小验证策略

1. 先跑直接相关的单测。
2. 再跑全量 pytest。
3. 跑 Ruff check、format check 和 mypy。
4. 修改前端时跑 Vitest、typecheck 和 build。
5. 修改跨端链路时跑 Playwright。
6. 修改文档时检查相对链接、命令和文件路径。

## 容易误判为“已验证”的情况

- 文件存在不等于功能可运行。
- mock transport 通过不等于真实 API smoke 通过。
- Playwright 脚本存在不等于浏览器二进制已安装并执行。
- fake 模式通过不等于 live 模式通过。
- 配置开关存在不等于执行路径真正消费了该开关。
- `summary.json` 存在不等于评测有效；还要检查 commit、数据哈希、judge 和失败率。

## 提交前检查

```powershell
git status --short
git diff --check
git diff --stat
git diff --name-only
```

仓库可能存在其他人或其他 Agent 的未提交改动。提交前必须精确 `git add` 本次文件，不得使用无差别 `git add .`。
