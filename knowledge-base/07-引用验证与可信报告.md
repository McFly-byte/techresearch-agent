# 引用验证与可信报告

## 目标

项目不把“报告里有 URL”当作引用可信，而是要求建立：

```text
事实 Fact → 声明 Claim → 引用 Citation → 重新抓取的证据 Evidence → 判定 Verdict
```

## 验证流程

1. `facts_to_claims()` 将每条 Fact 转成 Claim，引用 ID 原样继承。
2. `CitationVerifier.verify()` 按 Claim 的引用 ID 找到来源。
3. 对每个来源重新执行 fetch，不复用 Worker 首次抓取的 snippet。
4. 在正文中定位与 Claim 内容词最相关的窗口，默认最多 1200 字符。
5. 如果没有任何有效内容词命中，直接判 neutral，不调用 NLI。
6. 对有效窗口调用 NLI：
   - `entailment`：来源支持声明。
   - `contradiction`：来源与声明矛盾。
   - `neutral`：证据不足。
7. 多来源同时出现支持和矛盾时标记 `conflict=True`，聚合结果为 neutral。
8. 所有来源都抓取失败时返回 `verdict=None`、`reason=all refetches failed`。
9. 所有 NLI 都失败时返回独立的 `nli_failed`，不得伪装成 neutral。

## fake 与 live 验证器

- fake：默认 `_heuristic_nli`，确定性、仅供测试。
- live：`LLMNLI` 使用 `QWEN_VERIFIER_MODEL`，Prompt 来自 Prompt Hub。

不得把 fake 验证结果描述为真实 NLI 准确率。

## 修订策略

`RevisionPolicy` 的默认规则：

- 矛盾：删除该 Claim，不继续作为事实展示。
- 中立：改写为明确的不确定表达。
- 回查失败：保留审计状态，进入限制部分，不当作已验证事实。
- 被改写且未删除的 Claim 最多再验证一次。

每次修订写入 `RevisionRecord`，包含旧文本、新文本、原因和引用 ID。

## 来源策略

在验证前会再次应用 `SourcePolicy`：

- 移除禁用 URL、域名和标题。
- 移除截止日期之后的来源。
- 事实的引用只剩允许集合；若为空则删除事实。
- 日期无法确认的来源可保留并标注。

因此来源策略是双层防线：Worker 抓取前过滤，报告构建前复检。

## 输出

### Markdown

确定性模板包含：

- fake 模式警告。
- 来源约束审计。
- 验证统计。
- 已验证声明。
- 存疑/矛盾声明。
- 限制。
- 引用列表。

### HTML

所有用户文本与来源文本经过 HTML 转义。只有 `http://` 与 `https://` 地址可成为链接，其他 scheme 仅显示为普通文本。

### live 模式综合

有真实 LLM 时，Builder 会将已验证或降级后的 Claim 及允许的 Citation 重新编号为 `[c1]...[cN]`，再请求模型生成结构化报告。

质量门禁检查：

- 报告长度足够。
- 不是原问题回显。
- 存在引用标签。
- 所有引用标签都能映射到来源。
- 引用集合非空。

门禁不通过时，Runner 将任务标记为 failed。

## 修改验证逻辑的测试重点

- 不相关首段不能导致误判。
- NLI 异常不能变成 neutral。
- 多来源冲突必须显式呈现。
- 重新抓取确实发生。
- 修订轮次严格有上限。
- 危险 URL scheme 不可点击。
- 未知 citation_id 必须失败。
- blocked/post-cutoff 来源不能进入最终引用。
