# 评测体系

## 目录职责

```text
evals/
  adapter.py      数据集与结果模型、DRB2 适配
  baselines.py    答题器/基线装配
  configs.py      完整系统和消融配置
  metrics.py      KeywordJudge、LLMRubricJudge、聚合指标
  runner.py       可续跑执行、结果落盘、LangSmith Experiment
  failures.py     失败分类
  charts.py       从结果生成 HTML/SVG 图表
  cli.py          tra-eval 命令
```

## 数据隔离

研究 answerer 只能接收 `EvalPrompt`：

- qid
- question
- 研究时来源限制
- 截止日期

它不能读取 `reference_answer` 和 `rubrics`。完整 `EvalQuestion` 只在 judge 阶段使用，防止答案泄漏。

## 支持的数据集

### FixtureDataset

- 3 个合成问题。
- 用于离线 smoke 和测试。
- 不是正式 benchmark，结果不能宣传为模型成绩。

### DeepResearch Bench II

`DeepResearchBench2Adapter` 读取用户本地 JSONL：

- 解析 prompt、语言、主题、license。
- 展平三个 rubric 维度。
- 兼容 blocked rubric 列表与旧 blocked source 结构。
- 从 prompt/元数据提取禁用 URL、域名、标题和 as-of 年份。
- 对非法 JSON 或缺少 prompt 的行记录 adapter error，不静默忽略。
- 计算原始数据文件 SHA-256 写入运行元数据。

数据集目录被 `.gitignore` 排除，不应提交第三方大文件。

## CLI

离线 smoke：

```powershell
.\.venv\Scripts\tra-eval.exe run --mode fake --judge keyword
```

真实数据子集：

```powershell
.\.venv\Scripts\tra-eval.exe run `
  --dataset 路径\dataset.jsonl `
  --mode live `
  --judge llm `
  --limit 3 `
  --output-dir evals\runs\pilot
```

恢复：

```powershell
.\.venv\Scripts\tra-eval.exe run `
  --dataset 路径\dataset.jsonl `
  --mode live `
  --judge llm `
  --output-dir evals\runs\pilot `
  --resume
```

若没有 `--limit` 且没有 `--confirm-full`，CLI 自动限制为 3 题 smoke。`--concurrency` 当前只是保留参数，实际仍串行。

## Judge

### KeywordJudge

离线关键词匹配，仅用于测试和降级，不代表人工或高质量 LLM judge。

### LLMRubricJudge

- 按 rubric 批量评分。
- 支持批次并发和缺项单条重试。
- blocked rubric 记为 -1，不调用模型且不进入均值。
- 每题有硬超时；超时项使用稳定的 `judge_timeout` 结果。

当前工作区存在尚未提交的评测超时/并发改动，编写文档或提交时必须避免误覆盖。

## 运行产物

典型输出目录：

```text
evals/runs/<run>/
  config_snapshot.json
  results/<qid>.json
  summary.json
```

快照应包含配置、Python、平台、Git commit、Prompt 版本、数据集哈希、Provider 与模型信息。Runner 支持跳过已完成题并重试失败题。

## 消融配置

`CONFIGS` 包含：

- `llm_only`
- `naive_rag`
- `full`
- `no_verifier`
- `no_reflection`
- `single_agent`
- `no_long_term_memory`

维护消融实验时必须确认开关真的接入执行路径；仅在配置对象中存在字段并不等于已实现消融。

## 评测结论口径

- fixture 结果只能写“管线通过”。
- smoke 只能说明少量样本可运行。
- 正式结论必须记录数据集版本/哈希、代码 commit、Prompt commit、模型、judge、失败样本和成本口径。
- API 失败样本保留在分母中。
- 不得把预期数字、旧运行或已归档无效运行作为当前成绩。
