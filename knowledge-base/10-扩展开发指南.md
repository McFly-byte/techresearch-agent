# 扩展开发指南

## 新增 LLM Provider

1. 继承 `BaseLLMProvider`。
2. 实现 `acomplete()`、`is_configured()`，必要时实现 `with_model()`。
3. `model_id` 覆盖必须是单次请求级别，不能修改共享实例。
4. 返回 `LLMResponse`，正确标记 `usage_estimated`。
5. 在 `core/providers/factory.py` 接入配置解析。
6. 增加无网络的 mock transport 契约测试。
7. 更新 `.env.example`、配置文档和 doctor 输出。

## 新增搜索 Provider

实现：

```python
async def search(query: str, max_results: int = 5) -> list[SearchResult]
```

要求：

- 有超时、有限重试和明确的不可重试错误。
- 不在错误中泄露 Key。
- 截断过大返回体。
- 保持 URL、标题、snippet 和 source 字段。
- 可由 fake 测试替代。

接入主链路时更新 `_live_kit()`，不要让 fake 模式构造真实客户端。

## 新增 Fetcher

实现：

```python
async def fetch(locator: str, *, citation_id: str) -> SourceDocument
```

原则：

- 预期解析/读取失败返回 `fetched_ok=False`。
- 参数错误、越界路径等程序性问题可抛 `ToolError`。
- 保留 locator、citation_id 和错误 provenance。
- 设置大小与时间上限。
- 本地文件必须限制在允许根目录内。

## 新增 Planner

实现统一 `Planner` 协议：

```python
async def decompose(
    query: str,
    *,
    user_context: str = "",
    research_depth: ResearchDepth = "standard",
) -> list[SubTask]
```

计划必须通过 `ensure_valid_plan()`。LLM Planner 若输出结构化数据，只允许有限修复，不能无限重试。

## 新增图节点或状态字段

1. 在模块级定义 TypedDict/Pydantic 类型，避免类型提示解析问题。
2. 决定字段是覆盖语义还是 Reducer 合并语义。
3. 并发字段的 Reducer 要证明交换性、结合性、幂等性。
4. 更新节点边和循环硬上限。
5. 增加并发顺序反转测试。
6. 更新 API 暴露边界，禁止直接返回内部 state。

## 修改 Worker

必须保护以下边界：

- 取消可中断正在等待的搜索、抓取和提取。
- 搜索与输入长度有硬上限。
- 错误按类型决定是否重试。
- 原始异常和含凭证 URL 不进入 errors/trace。
- LLM 调用前预留预算，所有退出路径关闭票据。
- 事实保留来源 ID 与 source_task_id。
- 每个循环都有明确最大次数。

## 新增报告格式

新增格式应基于已经过来源过滤和验证的 `VerifiedReport` 数据，而不是绕过验证直接使用原始 Fact。HTML/富文本输出必须：

- 转义用户与来源内容。
- 过滤危险 URL scheme。
- 保持引用 ID 可追溯。
- 标示不确定、回查失败和删除状态。

## 新增记忆能力

- 默认关闭。
- 只有明确同意的结构化偏好或结论摘要可写入。
- 不存原始文档正文、完整 Prompt 或私密内容。
- namespace 必须是 `user/<id>`、`project/<id>` 或 `session/<id>`。
- 新 key 必须进入 allow-list，并补越权与隔离测试。

## 新增评测配置

- Answerer 只能看到 `EvalPrompt`。
- Judge 才能读取 rubrics/reference。
- 配置开关必须真正改变执行路径。
- 运行快照必须能定位数据、代码、Prompt、模型和 judge。
- 失败样本不能被静默排除。

## 文档同步要求

任何公共行为变化，都应同时更新：

- 根 `README.md`。
- `knowledge-base/` 对应章节。
- `.env.example` 或接口示例。
- 相关测试和历史手册中仍被引用的内容。
