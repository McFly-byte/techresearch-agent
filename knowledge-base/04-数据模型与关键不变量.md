# 数据模型与关键不变量

## 主要领域模型

定义位置：`src/domain/models.py`、`src/domain/verification.py`、`src/graph/state.py`。

### Citation

表示一个可追溯来源，核心字段包括：

- `citation_id`
- `kind`
- `locator`
- `title`
- `snippet`
- `source_task_id`
- `fetched_at`

### Fact

表示从来源中提取的事实，至少包含：

- `fact_id`
- `claim`
- `source_citation_ids`
- `source_task_id`

### SubTask

表示 Supervisor 调度的最小任务单元，包含依赖、优先级、状态、结果摘要、停止原因和重规划来源。

状态集合：

- 非终态：`pending`、`running`
- 终态：`completed`、`failed`、`cancelled`、`partial`

### Claim 与 VerificationResult

报告验证阶段将 Fact 转为 Claim，并保存逐来源证据、判定、验证轮次、冲突状态和失败原因。

### TaskRecord

API 层任务记录，保存公开任务信息、事件、Markdown/HTML 报告、错误、引用、用量和报告质量。

## Reducer 不变量

### 1. 终态不可复活

SubTask 进入终态后，不允许被后续的 pending/running 更新覆盖。

### 2. 成功优先

同一 task_id 同时出现 completed 与其他终态时，completed 稳定胜出，防止迟到的失败覆盖成功。

### 3. 并发合并确定性

Facts、Citations 和 Errors 的合并满足：

- 按 ID 或内容去重。
- 同 ID 冲突用排除时间戳后的规范化序列化选择稳定 winner。
- 输出排序稳定。
- 不依赖 Worker 完成顺序。

这些规则应保持交换性、结合性和幂等性。

## 事实—引用不变量

1. 每条事实至少引用一个 citation_id。
2. 引用 ID 必须存在于已收集的 Citation 集合。
3. LLM 提取的 claim 必须能在其引用的正文中逐字定位。
4. Worker 会为事实和引用写入 `source_task_id`。
5. 报告构建前再次检查未知引用 ID，发现即抛错。
6. 被来源策略移除的引用不能进入最终报告；若某事实失去全部来源，该事实也被移除。

## 预算不变量

1. LLM 调用前必须先预留最坏情况 token。
2. 预留是全有或全无，不返回部分额度。
3. 每张票据只能从 `reserved` 进入 `committed` 或 `released`。
4. 异常和取消路径必须释放票据。
5. 提交实际用量时账本不会超过硬上限；超出部分进入 `overflow_tokens` 并抛错。
6. 并发预留通过 `asyncio.Lock` 保护，但锁不能跨外部 I/O 持有。

## 来源约束不变量

`SourcePolicy` 同时作用于 Worker 搜索/抓取阶段和最终报告阶段：

- 精确 URL 禁用。
- 域名及子域禁用。
- 归一化标题匹配。
- 截止年份之后的材料移除。
- 无法确认日期时可以保留，但报告要标注日期未确认。

## 安全与隐私不变量

- 配置输出必须使用 `Settings.safe_dict()`，密钥只能显示为空或 `***REDACTED***`。
- 错误列表和 trace 不记录原始异常正文、Authorization、提示词或文档正文。
- HTML 输出必须转义用户和来源文本。
- 只有 http/https 引用可渲染为可点击链接。
- 长期记忆默认关闭；写入要求显式同意、允许类型、允许 key 和合法 namespace。

## 修改模型时的检查项

- 是否同步修改 Pydantic/Dataclass 模型、API 响应、持久化格式和测试？
- 新状态是否属于终态？Reducer 是否需要更新？
- 新字段是否含敏感信息？是否会进入日志、SSE 或持久化？
- 是否破坏旧 TaskStore JSON 的恢复兼容性？
- 是否仍能在并发 Worker 不同完成顺序下得到一致结果？
