# 已知限制与路线图

本页描述当前源码能确认的限制，不代表已经排期。

## P0：影响正确性或用户预期

### 1. HTTP API 无 live 模式入口

`ResearchRunner` 支持 fake/live，但 `POST /api/research` 的请求模型没有 mode，`create_app()` 使用默认 Runner，因此 API/前端默认只跑 fake。若要让 Web 使用真实研究，需要显式增加并验证 mode 选择，且不能让 live 静默降级。

### 2. 取消信号未真正连接到正在运行的 Worker

API 取消只设置 `TaskRecord._cancel_requested` 和状态；Runner 创建 Worker 时没有把该字段连接到 Worker 的 `cancel_event`。UI 会显示 cancelled，但后台协程可能仍继续工作。需要建立每任务取消事件或任务句柄，并验证中途停止。

### 3. FeishuExporter 未从 Settings 注入

`create_app()` 直接 `FeishuExporter()`，没有传入配置中的 App ID、Secret 和 folder token，因此默认接口会返回 `not_configured`。应显式从 `Settings` 构造，并保持密钥不进入日志。

### 4. TaskStore 持久化字段不完整

`_save()` 未保存 `mode`、来源约束、citations、usage 和 quality 等字段；恢复时这些信息会丢失。读取异常和保存异常也被静默吞掉。

## P1：生产化缺口

### 5. 任务系统是单进程内存模型

使用 `asyncio.create_task()`，没有队列、Worker 服务、租约或跨进程协调；服务重启会中断任务。

### 6. SSE 是轮询实现

事件保存在无界列表中，SSE 每 100ms 轮询，连接最长约 60 秒。大量任务或长任务需要事件总线、背压、分页/裁剪和心跳。

### 7. 无认证与多租户

所有任务和报告对可访问服务的人可见，没有用户隔离、授权、限流和审计。

### 8. 前端功能与本地化有限

界面文案主要是英文；`SafeMarkdown` 只支持少量 Markdown；错误页、重试、来源详情和完整问题链展示仍较简单。

### 9. HTTP 抓取缺少完整 SSRF 防护

当前检查 URL scheme，但生产环境还需阻止私网、回环、云元数据、重定向到私网、DNS rebinding 等风险。

## P2：能力完整性

### 10. 默认 Planner 仍是启发式

真实模式仍使用 `HeuristicPlanner`，没有接入 LLM 规划；对复杂研究问题的拆解能力有限。

### 11. 主流程未使用混合检索存储

`service/retrieval.py` 已实现 BM25、向量、RRF、Qwen embedding 和 SQLiteVectorStore，但 ResearchRunner/Worker 主链路目前未调用这些组件。

### 12. 长期记忆未接入 Runner

Runner 接受 `memory_store`，Settings 也有开关，但当前执行代码未读写长期记忆。

### 13. arXiv 未接入主图

论文检索存在于简单 CLI 管线，完整 Supervisor-Worker 主流程使用 Web 搜索。

### 14. 报告 HTML 与 Markdown 功能有限

HTML 是简化的安全模板；live LLM 综合报告的 HTML 仍由验证 Claim 模板生成，和最终 Markdown 可能不是完全相同的表达结构。

## P3：评测与运维

### 15. 消融开关需逐项核实接线

`EvalConfig` 定义了多个开关，但新增/维护正式消融前必须验证 answerer 的实际执行路径确实遵从配置。

### 16. `--concurrency` 尚未实现评测并行

CLI 明确提示参数保留，当前仍串行。

### 17. 缺 CI、容器与部署配置

仓库当前没有 GitHub Actions、Dockerfile、生产配置或自动发布流程。

## 推荐优先顺序

```text
真实取消链路
  → API live 模式与配置注入
  → TaskStore 完整持久化和错误可见性
  → 生产抓取安全
  → 队列/SSE/认证
  → LLM Planner、检索和记忆接线
  → 正式评测与 CI/CD
```

每解决一项，应增加失败路径测试，并同步更新本页，不要只在历史实施文档中记录。
