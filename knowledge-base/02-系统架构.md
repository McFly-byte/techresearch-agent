# 系统架构

## 分层结构

```text
用户 / 浏览器 / CLI
        │
        ▼
FastAPI 与 ResearchRunner
        │
        ▼
LangGraph：Planner → Supervisor ⇄ Worker → Collector → Replan → Writer
        │                                  │
        │                                  ├─ 搜索 Provider
        │                                  ├─ 页面抓取
        │                                  ├─ 事实提取
        │                                  ├─ 反思与预算
        │                                  └─ 来源过滤
        ▼
VerifiedReportBuilder
        ├─ Claim 构造
        ├─ CitationVerifier 回查
        ├─ 修订策略
        ├─ Markdown / HTML
        └─ 报告质量门禁
```

## 各层职责

### 接入层

- `src/api/main.py`：HTTP 与 SSE 接口、请求 ID、中间件、错误响应。
- `src/cli/doctor.py`：CLI 命令。
- `web/src/App.tsx`：前端页面和安全 Markdown 渲染。

### 应用编排层

- `src/api/runner.py`：选择 fake/live 工具集，创建预算、Worker 和图，构建可信报告，写入 TaskStore，并发出 SSE 事件。
- `src/graph/builder.py`：定义 LangGraph 节点与边。

### Agent 层

- `agents/planner.py`：当前默认使用确定性的 `HeuristicPlanner`。
- `agents/supervisor.py`：纯函数调度，处理并发槽位和依赖。
- `agents/worker.py`：搜索、抓取、提取、反思的有界循环。
- `agents/reflection.py`：基于可观测信号决定停止或改写查询。
- `agents/budget.py`：并发安全的预算账本。
- `agents/errors.py`：错误分类、退避与敏感信息清洗。

### 能力层

- `tools/search_providers.py`：Tavily 与离线搜索实现。
- `tools/fetchers.py`：HTTP、Markdown、PDF 与 fake 抓取。
- `service/extractor.py`：启发式和 LLM 事实提取。
- `service/verifier.py`：引用回查与 NLI。
- `service/verified_report.py`：可信报告生成与修订。
- `service/source_filter.py`：禁用来源和截止日期规则。
- `service/retrieval.py`：BM25、向量、RRF、SQLite 向量存储。
- `service/long_term_store.py`：显式同意、命名空间隔离的长期记忆存储。
- `service/exporters.py`：飞书文档导出。

### 基础设施层

- `core/config.py`：环境变量和安全配置视图。
- `core/providers/`：统一模型接口、FakeLLM 和 Qwen。
- `core/prompts/`：本地 Prompt 清单、锁文件和 LangSmith 同步。
- `core/tracing.py`：No-op、测试记录器与 LangSmith 追踪。

## 关键依赖方向

- 业务模块依赖抽象或鸭子类型 Provider，不直接依赖特定厂商 SDK。
- Worker 依赖预算、搜索、抓取和提取器；图只负责状态流转。
- API 不直接暴露 LangGraph 内部状态，而是返回稳定的 Pydantic 响应模型。
- 报告验证独立于 Worker 首次抓取，防止用缓存片段自证。

## 当前图结构

```text
START
  → planner
  → supervisor
      ├─ Send(worker, payload) × N
      └─ 无可派发任务时 → replan
  → worker
  → collector
  → supervisor（循环）
  → replan
      ├─ 证据不足且预算允许 → 新增 follow-up → supervisor
      └─ 证据足够或达上限 → writer
  → writer
  → END
```

注意：图中的 `writer` 先生成基础 Markdown；API 主链路随后还会调用 `VerifiedReportBuilder` 做引用验证和最终报告生成。

## 设计上的重要取舍

1. **调度纯函数化**：`decide_dispatch` 不依赖网络或全局状态，便于验证边界。
2. **Reducer 确定性**：并发结果按 ID 去重并稳定排序，避免完成顺序影响最终状态。
3. **默认离线**：fake 模式不因环境中存在密钥而联网。
4. **真实模式失败关闭**：live 模式缺关键配置时明确报错。
5. **验证与生成解耦**：报告生成器不能自行宣布引用可信，必须经过独立回查。
