# 核心执行链路

## 1. 从 API 创建任务

`POST /api/research` 接收：

- `query`：必填，1～2000 字符。
- `user_context`：可选背景。
- `research_depth`：当前约定为 `quick`、`standard`、`deep`。

API 通过 `TaskStore.create()` 创建 `TaskRecord`，再用 `asyncio.create_task()` 启动 `ResearchRunner.run()`。

## 2. 选择运行模式

`ResearchRunner` 构造时默认 `mode="fake"`。

- fake：固定 SearchResult、FakeFetcher、FakeLLM；强制零网络。
- live：要求 Tavily Key 和真实 Qwen Provider；缺失时抛 `ConfigurationError`。

当前 HTTP 创建任务接口没有公开 mode 参数，因此默认 API 路径运行 fake 模式。评测工具可显式选择 fake/live；若未来给 API 增加 mode，必须同步更新请求模型、前端和安全检查。

## 3. 建立预算与 Worker

Runner 从 `Settings` 构造 `BudgetManager` 和 `ModelRouter`，然后创建 `WorkerNode`。主要约束：

- 全局 token 上限。
- 可选单任务 token 上限。
- 单任务搜索轮次上限。
- Worker 迭代上限。
- 重规划次数上限。
- warning/critical 阈值和便宜模型切换。

## 4. Planner 生成计划

默认 `HeuristicPlanner` 根据深度生成固定数量的子任务：

- quick：3 个。
- standard：4 个。
- deep：5 个。

对 “A vs B”“A 对比 B” 类问题，前两个任务分别研究两侧，其余任务依赖前两个任务完成。非对比类问题按架构、生态、权衡、生产就绪度和未来方向拆分。

计划进入图前会执行 `ensure_valid_plan()`，检查：

- task_id 唯一。
- 依赖存在。
- 不允许自依赖。
- 依赖图无环。

## 5. Supervisor 派发

`decide_dispatch()` 根据 pending/running/completed/failed 状态和 `max_workers` 返回：

- `dispatch`：派发当前可执行任务。
- `wait`：等待在途任务或依赖。
- `finish`：没有 pending/running 任务。

失败或取消会向依赖任务传播，避免图永久等待。

## 6. Worker 有界循环

每轮顺序如下：

```text
检查取消与预算
  → 占用搜索轮次
  → 输入长度检查
  → 搜索
  → 禁用来源过滤
  → 逐 URL 抓取
  → 选择当前模型
  → 预留 token 预算
  → 事实提取
  → 提交或释放预算票据
  → 基于可观测信号反思
  → 停止或改写查询进入下一轮
```

### 搜索

- 查询最长 1400 字符，过长会安全截断并记录结构化错误。
- Tavily 适配器有超时和有限重试。
- 精确 URL、域名和标题可在抓取前过滤。

### 抓取

- HTTP 正文经 Trafilatura 提取。
- 原始下载和正文长度均有上限。
- 预期内的抓取失败返回 `fetched_ok=False`，Worker 保留失败 provenance。

### 提取

- fake/无 LLM 时可使用启发式逐句提取。
- 有 LLM 时使用 `LLMFactExtractor`，要求输出 JSON。
- 每条事实必须引用已知 citation_id，且 claim 必须能在被引用正文中定位。
- 首次解析失败只允许一次受控修复，再失败回退到启发式提取。

### 反思与停止

反思不是 LLM 的主观投票，而是检查：新结果数、独立来源数、事实数、覆盖问题、失败次数、预算余量、查询漂移等信号。

终止结果映射为 `completed`、`partial`、`failed` 或 `cancelled`，并记录结构化 `stop_reason`。

## 7. Replan

当一轮任务全部结束但事实少于阈值，且预算和重规划次数仍允许，图会增加一个 follow-up 子任务。新增任务保存：

- `replan_of`
- `gap_reason`
- `gap_source_task_ids`

相同证据缺口通过结构哈希去重，避免重复追加。

## 8. 可信报告

图内 Writer 先生成基础 Markdown。Runner 随后：

1. 应用最终来源过滤。
2. 将事实转为 Claim。
3. 重新抓取每个引用。
4. 定位与 Claim 相关的证据窗口。
5. 做 NLI 判断。
6. 对矛盾声明删除，对证据不足声明降级表达。
7. 对可修订声明最多再验证一次。
8. 生成 Markdown 与安全 HTML。
9. live 模式可使用 LLM 综合报告，并通过非空、非问题回显、引用标签和引用可追溯性门禁。

## 9. 任务完成

Runner 将报告、引用、token 用量、质量门禁结果写回 `TaskRecord`，并发送 `done` 事件。空事实或空引用不会标记成功。
